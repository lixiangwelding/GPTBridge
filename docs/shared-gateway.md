# 多仓库共用一条 FRP 和一个 MCP 入口

适用：Coding Tools MCP Personal 0.3.1。所有仓库仍直接使用原有目录，不创建 worktree，不复制开发树。

## 最少操作

1. 在个人版左侧“添加工作区”登记每个要使用的仓库。仅登记目录，不需要逐个启动 MCP 或隧道。
2. 选择其中一个作为入口，在“配置”里的 **一个入口 · 多个仓库** 勾选其他仓库，确认并保存。当前入口仓库自动包含，不重复勾选自身。
3. 只在这个入口配置认证和一条 FRP，启动入口 MCP／隧道。连接器只连接这个入口的 `/mcp` 地址，其他成员不需要独立端口映射或独立公网地址。

```text
一个连接器 /mcp
       │
一条 FRP → 入口本地端口
       │
       ├─ workspace_id=A → 仓库 A 的文件、任务、命令
       ├─ workspace_id=B → 仓库 B 的文件、任务、命令
       └─ workspace_id=C → 仓库 C 的文件、任务、命令
```

例如，入口使用个人版默认分配的 MCP 端口 38766 时，FRP 指向 `127.0.0.1:38766`；这个数字只是示例，以界面实际端口为准。成员的配置仍保存各自端口，但共享模式不需要启动那些监听器。不要把同一个公网子域重复配置成多条相互冲突的 FRP 代理。

如果已经在“全局 FRP 配置”保存了服务器信息，入口直接选择该配置即可。复用 FRP 服务器配置与只暴露一个 MCP 地址是两件事：前者已有，后者由本版网关实现。

## 对话怎么用

正常说明仓库与任务，例如“在 codeVerify 仓库修这个接口”“切到另一个项目审查”。模型先调用 `workspace_list`，取得该入口明确允许的仓库 ID，再给每次工具调用传入 `workspace_id`。创建和恢复任务仍使用 `task_open`，不用复制初始化长模板。

没有 `workspace_id` 的业务工具调用会拒绝，不会猜测上一次操作的仓库。多个对话共享一个入口，也没有会互相覆盖的“全局当前仓库”。同一个任务 ID 放到错误的仓库会失败，不会跨仓库读取结果。

仓库成员不允许由远程工具随意添加目录，只能由本地主人在界面确认。工具清单以入口的工具档位为上限，成员继续检查自己的工具档位和命令策略；给只读成员发送写入工具不会因为入口可写而获得许可。

## 认证与修改约束

共享入口必须启用 OAuth 或 Bearer。**该入口的登录凭据可以访问全部勾选成员**，界面保存前有明确确认；这不是给不同用户分别分配仓库权限的多租户系统。不要共享入口凭据给不应访问这些仓库的人。

所有成员通过同一个 `/mcp` 和同一套入口认证，因此 OAuth discovery、authorize、token 路径也走这条 FRP。无需为每个仓库再配置一套 OAuth 回调路径。需要公网 HTTPS 和正确认证参数时仍遵循原入口要求，不绕过原有校验。

成员、目录或执行策略在入口启动时固定。个人版共享入口运行期间，界面和后端拒绝会改变该快照的配置修改；需要变更时先确认任务状态，再**手动停止个人版入口**、修改、重新启动。保存不会自动停止或重启任务，更不会停止另一套旧 MCP。

成员被入口引用时不能直接删除，需要先移除引用。相同实际目录不能重复注册。仓库根本身仍包含其子目录；将父目录作为仓库意味着它可以访问自身内部的子目录，不能把嵌套目录当成相互隔离的安全域。

## 支持范围与真实边界

第一版共享入口聚合内置编码、历史和个人任务工具；**不同时聚合各成员额外配置的外部 MCP**。已启用外部 MCP 的成员会被明确拒绝加入，不静默丢工具。外部 MCP 可继续使用独立入口。

一个入口最多包含 32 个仓库。HTTP 在途工具调用最多 32，超出返回 429；单请求体最多 2MiB。命令的 8 运行／2 重任务／32 排队与运行上限仍按仓库计算，不是整个桌面进程总计 8 条。只读、查询和独立任务可并行；共享源码／产物写入继续受原有协作锁约束。

网关对文件读取采用 canonical 根目录检查，拒绝跨仓库绝对路径、`..` 和软链接逃逸。执行工具仍是受配置策略管理的本地执行，不是操作系统级沙箱；不要把任意脚本解释器标为只读，也不要把同一用户的本地进程当成隔离租户。

已验证临时双仓库通过同一个真实 loopback HTTP 入口访问、Bearer 拒绝、OAuth 发现与无效 token 拒绝、仓库选择、并行读取、任务与请求 ID 隔离、只读成员和输出归属。公网 FRP、用户实际 OAuth 登录、Windows 实机和原生 GUI 操作不是这些测试的替代结论；未执行时不会标成上线成功。

开发、自测和这份说明**不会修改当前正在运行的旧版 FRP 或旧 MCP**。升级旧连接需单独安排，不把未切换的旧连接误认作 0.3.1。

## 复验

```bash
python3 scripts/selftest_personal.py --suite all
python3 scripts/personal.py check-config
```

配置检查不启动服务。共享成员字段为入口 `runtime.gateway_workspace_ids`，日常从界面设置即可，不需要手写 JSON。

官方参考：FRP HTTP 路由 <https://gofrp.org/en/docs/features/http-https/route/>；MCP HTTP 授权与 discovery <https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization>。本版使用一条到入口的 FRP 转发，仓库路由发生在 MCP 工具调用层，不依赖按仓库划分的公网 URL。
