# 需求文档：desktop-local-delivery

## 功能概述
修复个人 MCP 在本机 Desktop 缺少可安装插件入口、生成文档交付位置不明确，以及应用更新后运行服务仍停留旧版本的问题。以 0.3.5/main 为基线；任务与配置必须保留。

## 历史经验与坑（来自记忆库）
磁盘替换不等于运行升级。系统拒绝辅助访问时不能依赖点击桌面按钮，也不能绕过系统权限。远程聊天能调用不等于 Desktop 已安装插件。并发时不能删除任务、重放未知结果或覆盖其他会话修改。

## 范围边界
In Scope：个人插件打包和安装、原生 stdio/HTTP 启动入口、本地路径交付、受控激活与验证、版本提交。
Out of Scope：修改 ChatGPT 闭源代码、强制刷新所有聊天、修改账号权限、关闭其他 MCP、承诺所有客户端缓存已同步。

## 需求列表
### FR-1: Desktop 可发现插件入口
优先级：Must。用户故事：作为本机用户，我要从已安装插件目录选择个人 MCP。
#### 验收标准（EARS）
WHEN 安装个人插件 THEN 系统 SHALL 注册独立个人插件名称、可读显示名、原生 MCP 与精简技能。
IF 客户端界面不可自动观察 THEN 系统 SHALL 区分“安装目录已识别”和“输入框实际显示已验证”。

### FR-2: 本地文件交付
优先级：Must。用户故事：生成文档后直接在工作区查看，不重复下载。
#### 验收标准（EARS）
WHEN 创建或修改文件成功 THEN 系统 SHALL 返回本地绝对路径，保留已有相对路径与哈希回执。
IF 补丁失败、预览或删除 THEN 系统 SHALL 不将其列为已交付文件。

### FR-3: 无界面启动与受控升级
优先级：Must。用户故事：升级后新服务实际可用，其他任务不被强制终止。
#### 验收标准（EARS）
WHEN 显式指定已保存工作区 THEN 系统 SHALL 支持无 GUI 的 stdio 或本地 HTTP 服务，沿用工作区、权限、任务库及 HTTP 鉴权。
IF 工作区不明确、端口占用或存在不安全切换条件 THEN 系统 SHALL 拒绝强停，不清理其他进程。
WHEN 新版本部署 THEN 系统 SHALL 分别记录构建、安装、监听版本、插件识别和任务恢复证据。

## 非功能需求
NFR-1：stdio 输入单帧不超过 2MiB，运行和排队有界；日志不得污染 stdout JSON-RPC。
NFR-2：既有 33 工具入参兼容、源锁和任务幂等规则不变；不放宽权限。
NFR-3：测试使用隔离状态；实际启用不通过辅助访问权限绕过，不自动重放任务。

## 依赖关系
已安装 Desktop 原生插件 CLI、Rust/Tauri 现有 MCP dispatcher、个人配置、macOS launchd（仅本机激活）。
