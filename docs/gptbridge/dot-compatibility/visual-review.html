## 图谱覆盖

写代码前使用受管 `mcp-probe-kit code_insight` 对 `load` / 精确 Svelte 文件 / UID 做 impact；当前 GPTBridge 索引未含该 Svelte 函数，不能从其他 Rust 同名函数推出影响。改动仅新增独立组件和页面 import/render，不改现有页面函数或共享 API。root 负责整体 detect_changes 和最终候选审阅。

## 最终验证

已真实编译并在独立 Vite 浏览器页面渲染 `DotWorkspacePanel.svelte`，采集 1440×900、375×844 与手机下半部截图。页面明确写“浏览器原生后端未连接”；唯一布局输入 `profile.id=layout-only` 是组件属性，不是实际工作区配置。没有 mock IPC、连接、任务、job、输出或成功结果。实际 API 的 `nativeAvailable()` 拒绝在浏览器中调用，组件据实展示“尚未观察 / 未验证 / 原生服务未连接”。这属于组件布局与错误反馈验证，不能替代完整工作区页面或 native 业务验收。

## 双引擎视觉指标

隔离临时目录安装 looks-same 10.0.1、pixelmatch 7.2.0、pngjs 7.0.0；没有改变项目依赖。`compare.mjs` 是可复跑脚本，`visual-metrics.json` 记录真实指标，两个引擎各输出独立 diff PNG。

| 比较 | looks-same equal | pixelmatch差异比例 |
| --- | --- | ---: |
| 附件desktop → 新静态prototype | false | 24.2737% |
| 附件375px → 新静态prototype | false | 14.9656% |
| 静态prototype desktop → 实际组件未连接态 | false | 4.9021% |
| 静态prototype375px → 实际组件未连接态 | false | 10.9858% |

这些比较不是逐像素同构：附件有整份方案文档的蓝色导航壳，现有应用使用绿色 token；静态prototype含示例任务，实际组件显示真实未连接错误。因此保留 `equal=false`，不将不同内容的像素差异包装成通过。人工 rubric 用于本次布局/层级门禁；实际 native 页面签收独立记录。

`ui-evidence.json` 固定附件 SHA、基线、组件源码 SHA 与验证层级。截图入口位于 `screenshots/`：source 为用户附件；prototype 为明确标注的静态设计；component-* 为无 native 后端的实际 Svelte 组件。
